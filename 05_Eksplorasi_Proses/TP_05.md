## 📝 Dasar Teori

Sistem operasi Xinu mengelola seluruh informasi proses melalui struktur data yang disebut **Process Table**. Setiap proses yang berjalan direpresentasikan sebagai satu entri dalam tabel ini.

### 1. Struktur Process Table

Implementasi tabel proses pada Xinu menggunakan array global bernama `proctab[]`. Setiap elemen dalam array ini adalah sebuah **PCB (Process Control Block)** yang didefinisikan dalam `struct procent` pada file `./include/process.h`.

### 2. Mekanisme Identifikasi (Implicit Data Structure)

Xinu menggunakan pendekatan *Implicit Data Structure*, di mana **Process ID (PID)** tidak disimpan sebagai variabel di dalam struct, melainkan menggunakan **indeks array** `proctab[]`. Sebagai contoh, jika kernel ingin memanipulasi proses dengan PID 3, maka kernel akan mengakses `proctab[3]`.

### 3. Source Code Utama Manajemen Proses

Beberapa file penting yang digunakan dalam pengelolaan proses pada Xinu adalah sebagai berikut:

* `./include/process.h` : Berisi definisi struktur `procent` dan berbagai konfigurasi proses.
* `./system/create.c` : Fungsi untuk membuat proses baru.
* `./system/kill.c` : Fungsi untuk menghentikan atau menghapus proses.
* `./system/resume.c` : Fungsi untuk melanjutkan proses yang sebelumnya ditangguhkan.

Melalui struktur dan fungsi-fungsi tersebut, Xinu dapat mengelola siklus hidup proses mulai dari proses dibuat, dijalankan, ditangguhkan, hingga dihentikan oleh sistem operasi.

### 1. Jawablah pertanyaan berikut!

#### a. Berapa banyaknya maksimum proses yang ada pada Xinu?

Jumlah maksimum proses yang dapat dikelola oleh sistem operasi Xinu adalah **50 proses**. Nilai tersebut ditentukan melalui konstanta `NPROC` yang terdapat pada file `process.h` dan digunakan sebagai ukuran dari tabel proses (`proctab`).

#### b. Berapa maksimal panjang nama suatu proses pada Xinu?

Panjang maksimum nama proses pada Xinu adalah **16 karakter**. Nilai tersebut ditentukan melalui konstanta `PNMLEN` yang terdapat pada file `process.h`.

#### c. Berapa nilai prioritas awal pada saat proses dibuat?

Prioritas awal proses pada Xinu tidak ditentukan secara tetap. Nilai prioritas diberikan melalui parameter `priority` saat fungsi `create()` dipanggil. Oleh karena itu, prioritas awal suatu proses bergantung pada nilai yang diberikan oleh programmer ketika proses dibuat.

#### d. Ada berapa total state pada Xinu? Sebutkan!

Xinu memiliki **7 state proses**, yaitu:

* `PR_FREE` : Slot proses kosong dan tidak digunakan.
* `PR_CURR` : Proses sedang dieksekusi oleh CPU.
* `PR_READY` : Proses siap dijalankan dan menunggu giliran CPU.
* `PR_RECV` : Proses sedang menunggu pesan.
* `PR_SLEEP` : Proses sedang berada dalam kondisi tidur (*sleep*).
* `PR_SUSP` : Proses sedang ditangguhkan (*suspended*).
* `PR_WAIT` : Proses sedang menunggu resource atau sinkronisasi.

### 3. Ubahlah perintah ps (source code: xsh_ps.c) pada Xinu sehingga menampilkan informasi tambahan berupa kolom yang berisi total message yang ada pada proses.

Pada tugas ini dilakukan modifikasi terhadap file `xsh_ps.c` agar perintah `ps` dapat menampilkan informasi tambahan mengenai pesan yang dimiliki oleh suatu proses.

Modifikasi dilakukan dengan menambahkan dua kolom baru yaitu:

* **Msg** : Menampilkan status keberadaan pesan pada proses melalui atribut `prhasmsg`.
* **Content** : Menampilkan isi pesan yang tersimpan pada proses melalui atribut `prmsg`.

Perubahan dilakukan dengan menambahkan kolom baru pada bagian header tabel dan menambahkan informasi `prhasmsg` serta `prmsg` pada bagian output setiap proses.
